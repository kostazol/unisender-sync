# Megaplan → Unisender

Лёгкая интеграция для автоматического переноса выбранных контактов из коробочного Megaplan в Unisender.

Клиенты и их сегменты ведутся в CRM, а рассылки — в Unisender. Утилита получает webhook об изменении карточки, читает актуальные данные и обновляет контакт в целевом списке. Если webhook теряется, можно включить резервный опрос изменений с момента запуска. Ручной экспорт CSV и постоянное копирование тегов не требуются.

## Как работает

1. Назначьте клиенту глобальную метку **Unisender** — это условие участия в синхронизации.
2. При изменении карточки Megaplan отправляет событие утилите.
3. Утилита сверяет email, членство в списке и теги через API обеих систем.
4. Отсутствующий контакт создаётся, недостающие теги добавляются, снятые — удаляются. При совпадении данных записи нет.

Передаются только **email и глобальные теги**, без ФИО и телефона. Управляющая метка в Unisender не копируется. Её снятие исключает контакт только из целевого списка. Отписка и блокировка подписчика не отменяются.

ID аккаунта, управляющей метки и списка определяются автоматически. Вы задаёте адрес CRM, UUID приложения, ключи и нужные названия. Отсутствующий именованный список создаётся при запуске с записью.

## Для кого и что нужно

- Коробочный Megaplan с API v3 и возможностью создать приложение.
- Обычный Unisender с доступом к API; Unisender Go не поддерживается.
- Компьютер или сервер, который видит оба API и принимает webhook от Megaplan.

Можно запустить обычную консольную утилиту, службу Windows/Linux или Docker-контейнер. Docker, Portainer, публичный домен и Graylog необязательны. Для коробочной CRM достаточно доступного внутреннего адреса webhook.

Базы данных и volume состояния нет. В RAM находится ограниченная очередь, история событий и короткий кэш. Логи пишутся в консоль; при настройке Graylog добавляется GELF UDP.

## Границы решения

- Синхронизация односторонняя. Резервный опрос охватывает только изменения с момента запуска.
- Теги Unisender общие для контакта: интеграция управляет всем их набором, отдельный список их не изолирует.
- Принятые события и история в RAM могут потеряться при остановке. Старый email удалённой карточки не всегда можно восстановить после потери кэша.
- Чтение тегов использует экспорт одного email, до 20 запросов в минуту. Более 10 тегов не обрезаются: событие завершается ошибкой.

## Разработка и выпуск

.NET 10, SDK-style solution `MegaplanUnisender.sln`. Сборка и тесты выполняются отдельно от Dockerfile:

```powershell
dotnet restore MegaplanUnisender.sln --configfile NuGet.Config
dotnet test MegaplanUnisender.sln -c Release --no-restore
```

Публикация GitHub Release запускает тесты и автоматическую сборку контейнера в GHCR. [Порядок выпуска версии](docs/PUBLISHING.md).

Локальные настройки, `.env`, `compose.override.yaml` и личные записи в `.local/` исключены из Git и Docker-сборки.
