# Настройка Megaplan

Нужен коробочный Megaplan с API v3 и права администратора для создания приложения.

## Создать приложение

1. Войдите в свою CRM, например `https://megaplan.example.com`.
2. Откройте **Настройки → Настройки системы → Интеграции → Глобальные → Приложения**.
3. Нажмите **Создать приложение**, задайте имя, например `Megaplan → Unisender`, и сохраните.
4. Оставьте **Только виджеты** выключенным: нужны доступ к API и события.
5. На вкладке **Настройки** скопируйте **UUID** и **API Token**.

UUID указывается в `Settings.Megaplan.ExpectedIntegrationUuid`, токен — в `Secrets.MegaplanApiToken`. Используется API Token приложения. Адрес CRM задаётся в `Settings.Megaplan.BaseUrl`: только HTTPS origin, без `/api/v3`, query и других путей.

В Compose эти поля называются `Settings__Megaplan__ExpectedIntegrationUuid`, `Settings__Megaplan__BaseUrl` и `Secrets__MegaplanApiToken`. Секрет подставляется через `MEGAPLAN_API_TOKEN`.

Проверьте доступ приложения к контактам, их email и глобальным меткам. [Справка Megaplan](https://support.megaplan.ru/settings/integration/global).

## Выбрать управляющую метку

Создайте глобальную метку **Unisender** через инструмент меток карточки контакта. Личная метка с таким именем не подходит. При другом названии измените `Settings.Megaplan.EligibilityGlobalTagName`.

Управляющая метка означает, что контакт нужно синхронизировать. Она не передаётся в Unisender. Остальные глобальные метки переносятся по текущим именам.

Числовые ID искать не нужно: при старте утилита получает идентичность аккаунта и справочник глобальных меток через API. Имя управляющей метки должно быть уникальным. После её переименования обновите настройку перед следующим запуском.

## Подключить webhook

Сначала запустите утилиту одним из способов из [руководства запуска](RUNNING.md).

1. Выберите адрес, доступный **с сервера Megaplan**. Для коробочной версии это может быть внутренняя сеть; публичный домен необязателен.
2. Сгенерируйте WebhookSecret командой `generate-webhook-secret` и сохраните его в `Secrets.WebhookSecret` или переменной Compose `WEBHOOK_SECRET`.
3. Укажите в приложении Megaplan на вкладке **События** полный URL:

```text
https://hooks.example.com/webhooks/megaplan/<WebhookSecret>
```

4. Включите поток **Контакты** (`contractors`), сохраните настройки и включите приложение.
5. Измените глобальную метку тестовой карточки с email и проверьте событие в логах утилиты.

При прямом доступе из локальной сети пример адреса — `http://192.0.2.10:5080/webhooks/megaplan/<WebhookSecret>`; замените хост своим доступным адресом. Windows-утилита по умолчанию слушает только `127.0.0.1:5080`. Для сетевого доступа задайте нужный `--urls`, например `http://0.0.0.0:5080`.

Если используете HTTPS reverse proxy, передавайте на HTTP-порт утилиты весь путь и тело запроса. Порт опубликованного Docker-примера — 5080. Не сохраняйте полный секретный URL в access log proxy.

Маршрут принимает только POST. GET из браузера не проверяет доставку события. Отдельных `/admin` и `/health` у утилиты нет.

## Первый контакт

Назначьте клиенту с email управляющую метку и обычный глобальный тег. Ожидаемый результат: email появляется в целевом списке Unisender с обычным тегом, без ФИО, телефона и управляющей метки.

Сам запуск не переносит всю базу CRM: нужен webhook или `sync <ID>` в основном терминале. В dry-run ожидается статус DryRun без внешней записи. [Сценарии проверки](MANUAL_API_TESTS.md).
