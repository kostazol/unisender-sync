# Ручная проверка API и синхронизации

Используйте отдельный тестовый контакт с доступным вам email. Подставляйте его ID и адрес вместо значений примеров; результаты с данными своего аккаунта сохраняйте локально вне отслеживаемых Git файлов.

## Проверка подключения без записи

Команда check запускается отдельным процессом, принудительно использует dry-run и не изменяет удалённые данные:

```powershell
.\MegaplanUnisender.Api.exe --command check
.\MegaplanUnisender.Api.exe --command tags
.\MegaplanUnisender.Api.exe --command lists
.\MegaplanUnisender.Api.exe --command 'card 12345'
.\MegaplanUnisender.Api.exe --command 'contact test@example.com'
```

Для check именованный список должен существовать: dry-run его не создаёт. При обычном запуске с записью отсутствующий список создаётся автоматически.

## Доставка webhook

Настройте в приложении Megaplan URL событий и поток contractors по [README](../README.md). Запустите утилиту, измените глобальный тег тестовой карточки и проверьте событие в основном терминале:

```text
status
configuration
events 12345
```

Ожидается новый UUID события, корректный model и on_after_update. В dry-run обработка заканчивается статусом DryRun, без записи в Unisender. Измените и снимите тег повторно; убедитесь, что Megaplan доставляет оба события. Планового поиска пропущенных изменений нет.

## Запись в Unisender

Установите Sync.DryRun=false. У тестового клиента должны быть email и управляющая глобальная метка, по умолчанию Unisender.

1. Добавьте обычный тег segment-a: контакт должен появиться в целевом списке с этим тегом и без управляющей метки.
2. Добавьте segment-b, затем снимите segment-a: итоговый набор должен совпасть с Megaplan.
3. Снимите последний обычный тег: контакт остаётся в списке с пустым набором тегов.
4. Снимите управляющую метку: контакт исключается только из целевого списка.
5. Повторите событие без изменения данных, затем перезапустите утилиту и повторите ещё раз: совпадающее состояние не должно вызывать subscribe или importContacts.
6. Измените теги непосредственно в Unisender и отправьте новое событие Megaplan: обработчик должен обнаружить расхождение.

По умолчанию передаются только email и теги. Изменение ФИО само по себе не вызывает записи. Если заданы FieldMappings, проверяйте их отдельно.

Проверьте отписанный, заблокированный и ожидающий подтверждения контакт: утилита не должна принудительно возобновлять подписку. Проверяйте сценарии смены email и удаления с учётом ограничений короткого кэша, описанных в [REVIEW.md](REVIEW.md).

## Ошибки и повтор

Неудачная или неполная выгрузка тегов не разрешает запись. Временный отказ должен привести к повторной сверке API. Для события со статусом Failed или Uncertain доступна команда retry <uuid> в основном процессе; при повторе исходный HTTP-запрос не отправляется вслепую.

Ошибки видны в консоли и, если он настроен, Graylog. Не публикуйте локальные выгрузки контактов и логи с данными своего аккаунта. Автоматические тесты используют фиктивные HTTP-ответы; намеренно исчерпывать тариф или менять реальные контакты ради проверки отказов не требуется.

Специальная команда live-test предназначена для одного Diagnostics.TestEmail при EnableLiveTests=true и отключённых связанных автоматизациях. Её параметры описаны в [CLI.md](CLI.md).
