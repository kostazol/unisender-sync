# Архитектурные решения и ограничения

Утилита обрабатывает webhook Megaplan, читает актуальные данные обеих систем и применяет необходимые изменения в Unisender. Состояние клиентов не хранится в базе данных или на диске.

## Структура решения

- Core: настройки, контракты, нормализация email и правила работы с тегами.
- Infrastructure: HTTP-клиенты, разрешение имён меток и списка, ограничение запросов, очередь и обработчик.
- Api: единственный маршрут webhook, консольные команды, DI и логирование.
- UnitTests и IntegrationTests: правила синхронизации, HTTP-контракты, обработка событий и диагностические команды с подменой внешних API.

Проекты используют SDK-style .NET. Общие файлы доступны в Solution Items и папках решения Visual Studio. Консольный запуск основной; Docker и Graylog подключаются по необходимости.

## Источники данных и запросы

При старте определяется идентичность аккаунта Megaplan, ID управляющей метки и ID именованного списка Unisender. Найденные ID используются повторно в текущем процессе. Массового обхода CRM и фоновой сверки нет.

Каждое событие перечитывает актуальную карточку. Перед записью сверяются членство, статус подписчика и теги Unisender. Теги читаются экспортом одного email; при совпадении запись не выполняется, включая обработку после рестарта. Добавление передаёт недостающие теги, удаление — итоговый набор. Отписка и блокировка контакта не отменяются.

Очередь ограничена QueueCapacity. История хранит до QueueCapacity + 1000 событий. Короткие подсказки ID/email ограничены RecentContractorCacheCapacity и RecentContractorCacheTtl; по умолчанию это 256 записей и 5 минут. Полные карточки и снимки применённых тегов не сохраняются.

## Отказы и остановка

Временные ошибки и неизвестный результат записи повторяются с backoff. Повтор заново сверяет API. После исчерпания попыток конкретное событие получает Failed или Uncertain; последующие события продолжают проверять фактическое состояние.

HTTP 200 подтверждает приём в RAM. Принятые события могут потеряться при остановке процесса. Для удалённой карточки после истечения подсказки старого email недостаточно события с одним ID. Исторические владельцы общего email также не восстанавливаются после потери кэша. Exactly-once не гарантируется.

## Конфигурация и журналирование

Обычные параметры находятся в Settings. Секреты поступают из .NET User Secrets при локальной работе или Secrets__... в окружении. Локальные appsettings.Local.json, Compose overrides, .env и личные заметки исключены из Git и контекста сборки Docker. Публикация приложения не включает appsettings.Local.json.

Serilog пишет JSON в консоль; при заданном адресе Graylog добавляет GELF UDP. Payload, email, API-ключи и полный секретный URL webhook в журнал не выводятся. При ошибках синхронизации записываются безопасные коды и контекст события.

Ручные сценарии приёмки описаны в [MANUAL_API_TESTS.md](MANUAL_API_TESTS.md), особенности API — в [API_COMPATIBILITY.md](API_COMPATIBILITY.md).
