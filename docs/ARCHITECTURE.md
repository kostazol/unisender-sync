# Архитектура первого этапа

Minimal API принимает webhook, проверяет секрет URL, приложение, аккаунт, UUID, тип и размер JSON. Поддержанные события помещаются в ограниченный .NET Channel; неподдержанные безопасно пропускаются. При переполнении возвращается 503, после принятия в память — 200.

Один BackgroundService последовательно читает Channel. Для события он получает актуальную карточку Мегаплана, вычисляет желаемые поля и теги и вызывает Unisender. Даже событие удаления сначала проверяет текущее состояние, чтобы старое событие не исключило заново созданную карточку.

SyncRuntime — singleton с ограниченной очередью, историей UUID/статусов событий и короткими подсказками ID → email/eligible. Подсказки имеют абсолютный TTL 5 минут и лимит 256 записей; истёкшие/старейшие записи удаляются при обращении. Это не копии карточек: поля и теги в runtime не сохраняются. Кеша успешно применённых тегов/полей/членства и блокировок email нет. Временное состояние хранится в памяти процесса и очищается после перезапуска.

Опциональный `ContractorPollingWorker` читает страницы изменённых карточек по `timeUpdated`, начиная с запуска приложения. Он использует общий лимит запросов Мегаплана и ставит в ту же очередь события обновления. При заполнении очереди опрос ждёт свободного места. Граница окна сдвигается после успешного прохода и хранится в памяти.

Core содержит настройки, Secrets, контракты HTTP-клиентов, нормализацию и политику тегов. Infrastructure содержит HTTP-клиенты, SyncRuntime, WebhookProcessor и WebhookWorker. Api задаёт единственный HTTP-маршрут webhook, CLI и зависимости. Состояние и повтор событий доступны только в терминале текущего процесса; локальных или удалённых HTTP-методов управления нет. Одноразовые команды диагностики не запускают HTTP-сервер и worker.

При Enabled=true до запуска worker и HTTP-сервера ConfigurationDiscovery получает идентичность аккаунта, MegaplanTagResolver читает глобальные метки с пагинацией, затем getLists определяет целевой список по названию. Если список отсутствует, в режиме записи вызывается createList; результат хранится в памяти и переиспользуется обработчиком. В dry-run список не создаётся. Без ключа Unisender dry-run проверяет только Megaplan. В режиме записи дополнительно определяется форма ответа getContact для отсутствующего адреса. При Enabled=false стартовые обращения к API отключены.

Управляющая метка влияет только на Contractor.Eligible и исключается из Contractor.Tags по ID. Остальные глобальные метки передаются под текущими именами. FieldMappings по умолчанию пуст: во внешний контакт отправляются только email и tags. Пустой набор очищается через importContacts без замены списков.

SyncAllGlobalTags=true по умолчанию переносит все глобальные метки по текущим именам. Справочник подтверждает глобальность известных ID; новые ID в карточках требуют явного isGlobal=true. Ручные TagMappings позволяют переопределять имена, а SyncAllGlobalTags=false возвращает выборочный режим. Неизвестная глобальность не считается разрешением. Из webhook не берутся ни базовый адрес API, ни токен, ни ожидаемая идентичность аккаунта.

Подсказка contractor ID → email позволяет обработать удаление недавно наблюдавшегося клиента или смену email. Это best-effort: после TTL, вытеснения или рестарта старый адрес из события с одним ID не восстановить. Незавершённые адреса ограничены тем же сроком/ёмкостью кеша. Общие адреса агрегируются среди недавних кандидатов; для каждого другого кандидата перед записью заново читается карточка Megaplan. Полного обхода CRM нет, кеш не содержит авторитетных тегов других клиентов.

На каждом событии getContact читает актуальные статус/членство. Для существующего допустимого контакта async/exportContacts экспортирует только email+tags одного email, async/getTaskResult возвращает подписанный CSV. CSV читается в память без API-ключа в запросе к хранилищу, без редиректов, с ограничением размера и проверкой единственности/адреса строки. Пустая или ошибочная выгрузка не считается пустым набором тегов. Текущий набор сравнивается с желаемым; совпадающее членство/теги/поля не вызывают запись даже после рестарта. Отсутствующему контакту экспорт не нужен.

Если контакт уже в целевом списке и поля не меняются, изменения тегов выполняет importContacts без изменения списков: только недостающие теги с overwrite_tags=0; при снятии тегов — полный желаемый набор с overwrite_tags=1. Документированная операция importContacts удаляет лишние метки через замену набора. subscribe используется для создания/включения в список и изменения дополнительных полей, а не для каждого добавленного тега.

По умолчанию дополнительные поля пусты: изменение только ФИО не вызывает внешней записи. При явном FieldMappings читаются текущие значения и отправляются только изменённые поля. Неизменные теги не отправляются. Exclusive владеет всеми тегами контакта; PreserveExternal не поддерживает точное зеркалирование без отдельного правила владения. Общий, subscribe- и export-бюджеты Unisender соблюдаются совместно; экспорт — не более 20 в минуту. Ожидание готовности ограничено 30 секундами, затем чтение может повторить worker.

Временные отказы чтения и неизвестный результат записи запускают повторную полную обработку с backoff, до MaxRetries. Повтор сначала читает фактические теги/членство, а не повторяет исходный HTTP-запрос. Совпадение не записывается. После исчерпания попыток конкретное событие получает Failed/Uncertain, без запрета для email. Следующее событие или обычный retry также сверяет API. Мгновенную согласованность внешнего API и exactly-once эта схема не гарантирует.

Журнал событий содержит UUID/ID клиента, статус, количество попыток и безопасный код ошибки. Payload, email и токены не логируются. Последние события ограничены QueueCapacity + 1000 записями; старые завершённые записи вытесняются. Настройки и секреты разделены по образцу Settings / Secrets и .NET User Secrets. Serilog интегрирован с Microsoft ILogger, Enrich.FromLogContext сохраняет scope обработчика. JSON stdout доступен всегда; при настройках Graylog добавлен Serilog.Sinks.Graylog с GELF UDP и полем application_name. Дополнительных HTTP endpoint, локальных файлов логов и доступа к данным Graylog из утилиты нет.
